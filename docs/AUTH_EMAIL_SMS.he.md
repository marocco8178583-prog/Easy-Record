# כניסה, הרשמה, תקנון, ושם האפליקציה באימייל וב-SMS

המדריך זהה ב-Easy Record וב-Find Medic. בכל אחת מהן מריצים את הסקריפט עם הפרויקט והשם שלה.

## מה כבר קיים באפליקציה
| | Easy Record | Find Medic |
|---|---|---|
| כניסה עם אימייל וסיסמה | ✅ | (בלי סיסמאות, בכוונה) |
| כניסה עם קוד באימייל | ✅ | ✅ |
| כניסה עם קוד ב-SMS | ✅ | ✅ |
| הרשמה | ✅ טופס הרשמה, וגם יצירת חשבון אוטומטית בכניסה הראשונה עם קוד | ✅ בכניסה הראשונה עם קוד, ואחר כך טופס עובד/מעסיק |
| אישור טלפון בהרשמה | ✅ מסך הזנת קוד ה-SMS | ✅ |
| קישור לתקנון ולמדיניות הפרטיות במסך הכניסה | ✅ | ✅ |
| תיבת "קראתי ואני מאשר/ת" לפני הרשמה או שליחת קוד | ✅ חובה | ✅ חובה |
| משתמש קיים שעוד לא אישר | נשאל פעם אחת אחרי הכניסה. "לא מאשר" מוציא מהחשבון | אותו דבר |

האישור נשמר בחשבון עצמו (`terms_version`, `terms_accepted_at`). כשהתקנון משתנה, מעלים את `TERMS_VERSION`
(ב-Easy Record: `src/js/32-auth.js`; ב-Find Medic: `src/lib/supabase.ts`), וכל המשתמשים יתבקשו לאשר שוב פעם אחת.

> התקנון ומדיניות הפרטיות הם עדיין **טיוטות**. לפני השקה צריך שעורך דין יעבור עליהם.

## מה עוד חסר בשרת (חד-פעמי, דורש חשבונות אצל ספקים)
כרגע **שליחת SMS לא מוגדרת** ב-Supabase של אף אחת מהאפליקציות, ולכן כניסה בטלפון מחזירה הודעה שמציעה אימייל.
והאימיילים נשלחים מהשולח הכללי של Supabase, ולא בשם האפליקציה.

### 1. אימייל בשם האפליקציה
שם השולח בתיבת הדואר (למשל "Easy Record") אפשר לקבוע רק עם שרת דואר משלך (SMTP). השולח הכללי של Supabase
מיועד לבדיקות: הוא שולח רק לחברי הצוות ומוגבל מאוד בכמות.
1. פותחים חשבון אצל ספק דואר, למשל Resend, Brevo או Postmark, ומאמתים דומיין, למשל `easyrecord.co.il`.
2. מקבלים פרטי SMTP: שרת, פורט, משתמש וסיסמה, וכתובת שולח כמו `no-reply@easyrecord.co.il`.

### 2. SMS בשם האפליקציה
1. פותחים חשבון Twilio בתשלום, יוצרים Messaging Service ומוסיפים לו **Alphanumeric Sender ID**: שם עד 11 תווים,
   באנגלית, למשל `EasyRecord` או `FindMedic`. כך ההודעה מגיעה מהשם הזה ולא ממספר.
2. בישראל השם נתמך, אבל ספקים מסוימים דורשים או ממליצים על רישום מראש. בלי רישום, חלק מהמפעילים
   עלולים להחליף את השם. מומלץ לרשום אותו ב-Twilio (Trust Hub).
3. רושמים בצד: Account SID, Auth Token ו-Messaging Service SID.

### 3. הרצת הסקריפט (מכניס את שם האפליקציה לכל האימיילים וה-SMS)
יוצרים Access Token ב-https://supabase.com/dashboard/account/tokens, ומריצים מתוך תיקיית הריפו:

```bash
export SUPABASE_ACCESS_TOKEN=sbp_...
# אופציונלי, אם כבר יש SMTP:
export SMTP_HOST=smtp.resend.com SMTP_PORT=465 SMTP_USER=resend SMTP_PASS=re_... SMTP_FROM=no-reply@yourdomain
# אופציונלי, אם כבר יש Twilio:
export TWILIO_ACCOUNT_SID=AC... TWILIO_AUTH_TOKEN=... TWILIO_MESSAGING_SERVICE_SID=MG...

# Easy Record
node tools/auth-branding.mjs --project bpxghjerbyqxtbszbpqj --app "Easy Record"
# Find Medic
node tools/auth-branding.mjs --project wgiahldrrnrqnlprbdyd --app "Find Medic"
```
`--dry-run` מציג מה ייקבע בלי לשנות כלום. בלי משתני SMTP ו-Twilio הסקריפט מעדכן רק את התבניות.

מה הסקריפט קובע:
- **כל תבניות האימייל** בעברית, מימין לשמאל, עם שם האפליקציה בכותרת ובנושא: אישור הרשמה, קוד כניסה (קוד בן 6 ספרות וגם קישור),
  איפוס סיסמה, שינוי אימייל, אימות חוזר והזמנה.
- **נוסח ה-SMS:** `123456 הוא קוד הכניסה שלך ל-Easy Record. אין למסור אותו לאף אחד.`
- עם SMTP: שם השולח = שם האפליקציה. עם Twilio: הפעלת כניסה בטלפון, ותוקף קוד של 5 דקות.

### 4. אחרי ההרצה
- ב-Find Medic: ב-Netlify מגדירים `VITE_EMAIL_OTP_CODE=true`, כדי שהאפליקציה תציג גם שדה לקוד מהאימייל
  ולא רק את הקישור. אחר כך מפעילים Deploy מחדש.
- בודקים בעצמכם: כניסה עם אימייל, כניסה עם SMS ואיפוס סיסמה, ומוודאים ששם האפליקציה מופיע בשולח ובתוכן.
- ב-Supabase, בעמוד Authentication ← Rate Limits, מעלים את מגבלת האימיילים לשעה. אחרי הגדרת SMTP היא 30 בהתחלה.
